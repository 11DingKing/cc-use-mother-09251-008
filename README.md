# 繁忙服务区分级发布

面向业务人员的纯服务端系统：维护指标版本、分级规则、观察期与人工例外，
生成内部候选清单，经双人复核后形成公开版本；紧急升级允许先发布后补审
并自动追踪补审期限；撤销只影响尚未结束的有效区间。内部与公众两套 API
权限隔离，公众渠道只能看到简化结论；提供历史重建与签名校验命令。

代码按领域模型、应用服务、持久化与接口边界组织；时间、标识和签名密钥
通过可替换端口接入（`ports.py`），以便稳定复现状态变化。运行数据与本地
配置写入数据目录（默认 `$XDG_DATA_HOME/service_09251_008` 或
`~/.local/share/service_09251_008`），不写入源码目录。仅依赖 Python 标准库。

## 结构

| 模块 | 职责 |
| --- | --- |
| `domain.py` | 等级、状态机、时间规范、分级规则求值（纯函数） |
| `services.py` | 应用服务：全部业务用例与状态迁移 |
| `storage.py` | SQLite 持久化：事务、并发串行化、审计哈希链 |
| `httpapi.py` | HTTP 接口边界：内部/公众两套 API、令牌鉴权 |
| `cli.py` / `__main__.py` | 服务启动与运维命令 |
| `ports.py` / `config.py` | 可替换端口（时钟/标识/密钥）与环境配置 |

## 运行

```bash
# 启动服务（启动前自动执行进程恢复）
python3 -m service_09251_008 serve --port 9251

# 运维命令
python3 -m service_09251_008 recover                       # 进程恢复：期限追踪 + 审计链校验
python3 -m service_09251_008 sweep                         # 标记超过补审期限的紧急升级
python3 -m service_09251_008 reconstruct --at 2026-10-01T23:00:00Z
python3 -m service_09251_008 verify-signature --version 1  # 退出码 0/1
python3 -m service_09251_008 verify-audit                  # 退出码 0/1
```

配置通过环境变量（前缀 `S09251_008_`）：`DATA_DIR`、`HOST`、`PORT`、
`INTERNAL_TOKENS`（`token:identity` 逗号分隔）、`PUBLIC_TOKENS`、
`SIGNING_KEY_FILE`、`EMERGENCY_REVIEW_HOURS`（默认 24）。
未设置时使用开发令牌 `dev-internal-alice/bob/carol` 与 `dev-public`。

## API 概览

- 内部（`/internal/**`，需内部令牌）：指标版本、规则版本（启用即切换，
  旧版本退役）、观察期与观测录入、人工例外、候选清单生成/提交/复核/发布、
  紧急升级与补审、公开条目撤销、历史重建、审计校验。
- 公众（`/public/**`，公众或内部令牌）：当前清单、指定版本的简化内容与
  签名。公众输出不含触发指标、复核人与内部备注。

关键语义：

- **双人复核**：两名不同复核人赞成方可发布；创建人不能自审；重复审批
  返回 409 `DUPLICATE_REVIEW`。
- **并发发布**：发布在立即事务内完成，版本号事务内分配；同一清单只能
  发布一次，同一观察期只能有一个公开版本。
- **紧急升级**：立即形成公开版本（`EMERGENCY`），补审期限到期未审自动
  标记 `OVERDUE`（读取时惰性追踪 + `sweep`/`recover` 主动追踪）；补审
  否决会截断尚未结束的条目。
- **撤销**：`valid_to <= now` 的区间拒绝撤销；进行中的区间在撤销时刻
  截断；未开始的区间整体失效。原始区间不改写，历史重建按撤销事件还原。
- **历史重建**：最近的 `NORMAL` 版本构成基线，其后的 `EMERGENCY` 版本
  叠加（同服务区后者覆盖前者），再按有效区间与撤销事件过滤。
- **签名**：公开版本内容（版本号、类型、发布时间、条目）的规范化 JSON
  计算 HMAC-SHA256；撤销不参与签名，作为事件记录在审计哈希链中。
